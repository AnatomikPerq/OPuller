# План исправлений OPuller по итогам выполнения уроков Illustrator

Источник замечаний: пять практических работ курса (сова, лиса, летний пейзаж, котёнок, рябина «Осень»)
выполнены в OPuller через MCP-мост по пошаговым урокам для Adobe Illustrator. Ниже — что мешало,
где это в коде и как чинить. Приоритеты: **P0** — блокирует/даёт неверный результат, **P1** — расхождение
с Illustrator, заметное при повторении урока, **P2** — скриптуемость и удобство, **P3** — желательное.

---

## P0 — блокирующие дефекты

### 1. MCP-мост не переподключается, если порт 5187 занят при старте
- **Статус.** СДЕЛАНО (322b0dc). Перебор портов 5187–5197 с ретраями, реестр портов + `/__opuller/bridge-ports`, PID процесса в ошибке; `mcp/smoke.ts` блокирует порт и требует ответ за ≤10 с.
- **Симптом.** `opuller_status` → «No OPuller editor is connected (bridge error: listen EADDRINUSE …)» для всей сессии, даже когда порт давно свободен.
- **Где.** `mcp/server.ts`: `startWebSocketServer()` вызывается один раз; при ошибке пишет `wsError` и больше не пытается.
- **Исправить.**
  - Повторять `listen` с backoff (1 с → 2 → 5 → 10, бесконечно) пока `wss === null`; на каждом вызове инструмента, если сервера нет, — попытка немедленно.
  - Если порт занят «живым» сервером OPuller (проверить хендшейком `hello` как клиент), переходить на следующий порт из диапазона `5187–5197` и сообщать редактору новый порт (через `/__opuller/bridge-port` на dev-сервере или query-параметр).
  - В сообщении об ошибке печатать PID/команду процесса, держащего порт (`netstat`/`lsof`), и подсказку.
- **Тест.** `mcp/smoke.ts`: поднять заглушку на 5187, запустить сервер, освободить порт — через ≤10 с `opuller_status` отвечает.

### 2. Радиусы углов прямоугольника обрезаются до половины меньшей стороны
- **Статус.** СДЕЛАНО (f063d2b). `clampRectRadii`: пара радиусов, не влезающая в сторону, масштабируется, остальные не трогаются; unit-тест 47×61 / [23.636, 23.636, 0, 37.3].
- **Симптом.** Тело совы (47×61 мм) с нижним левым радиусом 37 мм невозможно: радиус режется до 23,6. В Illustrator live corners допускают радиус до длины смежной стороны за вычетом соседнего радиуса.
- **Где.** `src/geometry/shapes.ts` → `rectSubPath`: `maxR = min(width, height) / 2` для всех углов разом.
- **Исправить.** Ограничивать каждый угол отдельно: `r_tl ≤ min(width − r_tr, height − r_bl)` и т.д. (при конфликте масштабировать пары пропорционально, как Illustrator/CSS `border-radius`). То же для `opuller_create_shape.radii`, панели Transform и корнер-виджетов.
- **Тест.** unit: прямоугольник 47×61 с `[23.636, 23.636, 0, 37.3]` даёт левую прямую грань длиной `61 − 23.636 − 37.3`.

### 3. Карандаш берёт заливку не из «текущего оформления», а из выделения
- **Статус.** СДЕЛАНО (8a34ce3). Инструменты рисования читают `state.appearance`; выделение делает стиль объекта текущим (как в Illustrator); `opuller_set_appearance {target}`; e2e.
- **Симптом.** `opuller_set_appearance(fill=X)` → `opuller_gesture(tool=pencil, fillStrokes)` — новый контур получает цвет предыдущего выделенного объекта (в работе «Котёнок» задняя лапа вышла цвета фона).
- **Где.** `src/tools/pencil/tool.tsx` → `pencilStyle()` → `currentAppearance()` (`src/commands/appearance.ts`): при непустом выделении возвращает оформление выделения; `keepSelected: true` оставляет предыдущий штрих выделенным; `setAppearance` из MCP при выделении меняет объект, а не значения по умолчанию.
- **Исправить.**
  - Развести два понятия: `state.appearance` (то, чем рисуют новые объекты) и «оформление выделения» (то, что показывает панель). Инструменты рисования читают только первое.
  - `opuller_set_appearance` — параметр `target: "defaults" | "selection" | "both"` (по умолчанию `defaults`).
  - Карандаш/перо/кисть при `editSelected: false` не должны наследовать стиль выделения.
- **Тест.** e2e: выделить синий круг, задать текущую заливку красной, нарисовать карандашом → путь красный, круг остался синим.

### 4. Экспорт AI (legacy) падает на документах со встроенными растрами
- **Статус.** СДЕЛАНО (68abcea). Причина была не в `fromCharCode`, а в `body.push(...lines)` (65k строк на картинку). Unit-тест 2000×2000; откат на PDF-совместимый .ai при сбое.
- **Симптом.** «Maximum call stack size exceeded» при экспорте «Осени» (пять JPEG ~1–2 МП). PDF-совместимый `.ai` работает.
- **Где.** `src/io/aiExport.ts` — вероятно `String.fromCharCode(...bytes)` / `apply` на больших массивах при кодировании изображений в ASCII85/Hex.
- **Исправить.** Потоковое/чанковое кодирование (по 8–64 КБ), без spread; при неудаче не бросать исключение, а автоматически падать на `aiFormat: "pdf"` с предупреждением в `warnings[]`.
- **Тест.** unit: экспорт документа с изображением 4000×4000 RGB не падает; smoke на реальном проекте `Осень (рябина).opuller`.

## P1 — расхождения с Illustrator, ломающие повторение уроков

### 5. Эффект «Warp → Bulge» даёт другую форму, чем Illustrator
- **Статус.** СДЕЛАНО. Illustrator установлен; через COM-мост (`scripts/illustrator/`) сняты решётки и контуры всех 15 стилей (bend ±10…±100, искажения, обе оси, неквадратные кадры — ~2000 случаев). Оказалось, warp в Illustrator — один бикубический Безье-патч 4×4; формулы восстановлены точно (`src/distort/warp.ts`), расхождение ≤ 0.06 px на всех случаях, включая случайные. Фикстуры `tests/fixtures/warp/*.json`, тест `tests/unit/warpFixtures.test.ts`. Прямые стороны вдоль осей теперь дают одиночные кривые (прямоугольник → 4 узла, как Expand в Illustrator).
- **Симптом.** Урок: треугольник + Выпуклость 40 % (вертикально) + искажение −10 % → ухо с мягко выгнутыми сторонами. В OPuller тот же набор даёт «луковицу»: стороны выпучены у основания, у вершины почти прямые. Подбирал форму вручную.
- **Где.** `src/distort/warp.ts` → `warpUnit()` (`bulge`, `hDistort/vDistort`).
- **Исправить.**
  - Снять эталонные растры всех 15 стилей из Illustrator (квадрат 200×200, bend ±25/±50/±100, distort ±30) и положить в `tests/fixtures/warp/`.
  - Пересчитать формулы по эталонам: у Illustrator bulge масштабирует поперечный размер по гладкому профилю `1 + b·sin(π·v)`-типа (без излома на середине), horizontal distortion — сдвиг перспективы, а не сжатие одной стороны. Считать по каждому стилю отдельно.
  - Добавить unit-тест «IoU с эталоном ≥ 0.97» для каждого стиля.

### 6. «Скругление углов» после варпа не действует; нет живых углов на уровне геометрии
- **Статус.** СДЕЛАНО (f063d2b). `anchor.cornerRadius` + корнер-виджеты Direct Selection, диалог Corners, `opuller_corners`; углы по излому касательных, обрезка через несколько сегментов — эффект Round Corners работает после warp; e2e-тест сценария.
- **Симптом.** Порядок `[warp, roundCorners]` оставляет вершину острой; работает только `[roundCorners, warp]`. В уроке кончик уха скругляют корнер-виджетом (это геометрия объекта, а не эффект).
- **Где.** `src/canvas/effectiveGeometry.ts` (порядок применения), реализация `roundCorners` (не находит «углы» после того, как warp насыпал плотные гладкие узлы).
- **Исправить.**
  - Live corners как свойство узла (`anchor.cornerRadius`) + корнер-виджеты для любого пути, не только для live-shape rect. Применяются до эффектов — как в Illustrator.
  - `roundCorners`-эффект: определять углы по излому направления (угол между входящей/исходящей касательной > порога), а не по типу узла; документировать, что эффекты применяются в порядке списка.
- **Тест.** e2e: треугольник → радиус вершины 9 → warp bulge 40 → вершина скруглена.

### 7. Нет эффектов Distort & Transform: Zig Zag, Roughen, Pucker & Bloat, Transform, Tweak
- **Статус.** СДЕЛАНО (bef3c86). Zig Zag, Pucker & Bloat, Roughen, Transform, Tweak — живые эффекты с диалогами, Expand, проект; unit-тест плана проходит. Pucker & Bloat и Zig Zag сверены с Illustrator 2026 и пересчитаны по его модели (`tests/fixtures/effects/*.json`, `scripts/illustrator/effect-fixtures.mjs`, расхождение ≤ 0.01 px): у Illustrator «ridges per segment» = число пиков на сегмент (не 2n−1), узлы контура тоже смещаются, ручки Pucker & Bloat идут от центра на тот же процент. Roughen/Tweak случайны (сверить можно только статистически), Transform — аффинный, Round Corners и Offset Path ещё не сверялись.
- **Симптом.** Рот котёнка (Zig Zag: size 4, ridges 3, smooth) пришлось рисовать вручную. Эти эффекты встречаются почти в каждом уроке Illustrator.
- **Где.** Новый модуль `src/distort/` (регистрация через `registerGeometryEffect` + `registerExpander`, диалог через `registerDialog`).
- **Исправить.** Реализовать в порядке частоты: Zig Zag (size абс./отн., ridges per segment, smooth/corner) → Pucker & Bloat → Roughen (size, detail, smooth/corner, seed) → Transform (копии, сдвиг, масштаб, поворот, отражение) → Tweak. Все — как живые эффекты с Expand Appearance.
- **Тест.** unit на геометрию Zig Zag: отрезок 100 px, size 4, ridges 3 → 7 узлов, амплитуда ±4.

### 8. Знак поворота противоположен Illustrator
- **Статус.** СДЕЛАНО (80e081f). MCP `transform.rotate`, `createShape.rotation`, `symbols place` — против часовой; HUD инструмента Selection; угол узора и вращение scatter-кисти тоже (миграция формата проекта 1 → 2).
- **Симптом.** `opuller_transform{rotate: +26}` поворачивает по часовой на экране; в Illustrator (и в `CLAUDE.md`) положительный угол — против часовой. Уши/ветку с листьями пришлось переворачивать по знаку.
- **Где.** `src/mcp/api.ts` (`transform`, `createShape.rotation`), инструмент Rotate, диалог Rotate, панель Transform — сверить все точки входа.
- **Исправить.** Единая конвенция «положительный = против часовой (на экране)» во всех API и UI; в `mcp/server.ts` описание параметра `rotate` — явно указать направление. Миграция: старые проекты хранят матрицы, их не трогать.
- **Тест.** unit: поворот точки (1,0) на +90° вокруг начала даёт (0,−1) в экранных координатах (y вниз).

### 9. Warp Tool (liquify) — иной характер деформации
- **Статус.** СДЕЛАНО в части профиля и интерполяции (e2cd5de): raised-cosine спад, подшаги без ограничения 8, интерполяция N точек и для таймерных кистей; e2e «мазок 120 через прямоугольник 300×200 → ≤40 узлов, без самопересечений».
- **Симптом.** Отражение кораблика в уроке — три-четыре широких мазка. В OPuller при ширине 110 px мазок «режет» фигуру на полосы, а мелких мазков шириной 80 нужно ~70, чтобы получить плавную рябь.
- **Где.** `src/liquify/*` (кисть warp: спад интенсивности, плотность узлов, `detail/simplify`).
- **Исправить.**
  - Спад по гауссу/`smoothstep` от центра кисти (сейчас, судя по результату, близко к ступеньке).
  - Автоматическая вставка узлов только там, где деформация превысила `detail`, и последующее упрощение (`simplify`) в пределах допуска — чтобы широкий мазок давал гладкую S-волну.
  - В `opuller_liquify` принимать путь мазка из N точек с интерполяцией (сейчас точки применяются как отдельные шаги).
- **Тест.** e2e: прямоугольник 300×200, один горизонтальный мазок шириной 120 через середину → контур остаётся односвязным, без самопересечений, число узлов ≤ 40.

### 10. Кириллический текст в AI уходит в кривые по умолчанию
- **Статус.** СДЕЛАНО (68abcea). `encoding: "auto"` выбирает cp1251, когда текст в основном кириллический; предупреждение называет кодировку и параметр; в диалоге экспорта появился выбор кодировки.
- **Симптом.** Предупреждение «text objects converted to outlines» для «Лисёнок». Параметры `text: editable, encoding: cp1251` есть, но их надо знать.
- **Исправить.** `text: "auto"` → если весь текст укладывается в cp1251, писать редактируемым с `encoding: cp1251` автоматически; в предупреждении подсказывать параметр.

## P2 — скриптуемость (MCP) и параметры диалогов

### 11. Диалоги без программного входа: Blend Options, Offset Path, Simplify, (будущие) Zig Zag/Roughen
- **Статус.** СДЕЛАНО (95bc7bd). `registerDialog(id, component, { apply })` + `runCommand(id, arg)`; инструменты `opuller_blend`, `opuller_offset_path`, `opuller_simplify`, `opuller_effect`.
- **Симптом.** Число шагов перехода задаётся только в диалоге — пришлось менять `<input data-testid="blend-steps">` через `opuller_eval`; Offset Path — вызов `offsetNodes()` через внутренний API.
- **Исправить (общий принцип).** Каждый диалог регистрирует `apply(params)` рядом с UI (`registerDialog(id, component, { apply })`), а `runCommand(id, arg)` при переданном `arg` вызывает `apply(arg)` без открытия диалога. В `mcp/server.ts` добавить типизированные инструменты:
  - `opuller_blend` — `op: make|options|expand|release|reverse`, `spacing`, `steps`, `distance`, `ids`.
  - `opuller_offset_path` — `distance`, `join`, `miterLimit`, `mode: new|replace`.
  - `opuller_simplify` — `tolerance`, `corners`, `straightLines`.
  - `opuller_effect` — `add|update|remove|expand`, `type`, параметры (сейчас эффекты правятся сырым `patch.effects`).
- **Тест.** smoke: `opuller_blend{op:"make", steps:6}` на двух листьях → группа из 8 детей.

### 12. Нет инструментов выравнивания/распределения и «Scale corners»
- **Статус.** СДЕЛАНО (95bc7bd). `opuller_align`; `opuller_transform {scaleStrokes, scaleEffects, scaleCorners}`.
- **Симптом.** Уроки: «Horizontal/Vertical Align Center», «выровнять по выделенной области», Transform → «Scale corners». Делал координатами.
- **Исправить.** `opuller_align` (`h: left|center|right`, `v: top|middle|bottom`, `to: selection|artboard|key`, `distribute: h|v`, `spacing`); в `opuller_transform` флаги `scaleCorners`, `scaleStrokes`, `scaleEffects` (сейчас только глобальный prefs.scaleStrokes).

### 13. Рисующие инструменты — прямые вызовы вместо имитации жестов
- **Статус.** СДЕЛАНО (95bc7bd). `opuller_pencil`, `opuller_pen`.
- **Симптом.** Карандаш только через `opuller_gesture` (оптимизация точек, closeDistance, editSelected — побочные эффекты); перо — только через `create_path`.
- **Исправить.** `opuller_pencil{points, fidelity, smoothness, closed, fill, stroke}` (вызывает `fitRuns` напрямую) и `opuller_pen{anchors:[{point, handleIn, handleOut}]}`. Жест оставить для тестов инструментов.

### 14. Pathfinder/минус-фронт: результат в виде составного пути с «огрызками»
- **Статус.** СДЕЛАНО (95bc7bd). `cleanup` (по умолчанию) удаляет субпути < 0.25 px² в результатах Pathfinder — и в UI, и в MCP.
- Не баг, но удобно: опция `cleanup: true` — удалять субпути площадью < ε после булевых операций и `path.cleanUp` по умолчанию в MCP.

### 19. Вертикальная линейка обрывается сразу под углом линеек

- **Где.** `src/canvas/Rulers.tsx`: холст вертикальной линейки создавался размером `длина × 20` (как горизонтальной), а рисовался как `20 × длина`.

### 18. Регрессионные фикстуры на основе уроков
- **Статус.** СДЕЛАНО. `tests/e2e/lessons/` — сборочные скрипты всех пяти работ (сова, котёнок, рябина, летний пейзаж, лиса; тексты уроков взяты из Google Classroom, «лиса» — это практическое занятие 2 «контуры, заливки, текст» с лисой в примере) через API + baseline-PNG (собственные рендеры OPuller, IoU ≥ 0.95, `UPDATE_LESSONS=1` перезаписывает). Эталоны из Illustrator: `tests/e2e/lessons-illustrator.spec.ts` (`ILLUSTRATOR=1`) экспортирует сборку в .ai, рендерит её самим Illustrator (`scripts/illustrator/render-file.mjs`) в `tests/e2e/lessons/illustrator/*.png`; обычная спека сравнивает с ними на каждом прогоне (IoU ≥ 0.93, цвет внутри фигур ≥ 0.97; сейчас сова 0.98 / котёнок 0.99 / рябина 0.97 / пейзаж 0.996 / лиса 0.99). `node scripts/run-lesson.mjs <name>` собирает один урок в открытом редакторе. Попутно найден и исправлен дефект Create Outlines: opentype.js 2.0 `toPathData()` печатал NaN для координат с крошечной дробной частью (например 125 × 0.072), из-за чего глифы обрезались («а» в Montserrat Bold превращалась в треугольник); контуры теперь сериализуются из команд напрямую (`glyphPathData`, тест в `tests/unit/text.test.ts`).
